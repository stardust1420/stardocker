# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

StarDocker is a Go terminal UI (Bubble Tea + Bubbles + Lip Gloss) for local Docker: containers (start/stop/restart/pause, shell, inspect, live CPU/memory, Compose stacks), logs, images, volumes and networks. Module path: `github.com/stardust1420/stardocker` (Go 1.24).

## Commands

```bash
go build .        # produces ./stardocker (binary is gitignored); --version / --help
go run .          # run directly; needs a reachable Docker daemon
go vet ./...
gofmt -l .
docker run -d --name stardocker-test alpine:3.20 sh -c 'i=0; while true; do i=$((i+1)); echo "tick $i"; sleep 2; done'   # test container that keeps logging; remove with docker rm -f stardocker-test. `sh` ignores SIGTERM, so stopping it takes ~10s and it exits with 137
```

Unit tests live in `src/*_test.go` (`go test ./src/...`; one test: `go test ./src/... -run TestName`). They cover only pure helpers; anything that calls Docker needs the daemon.
The TUI needs a real TTY, so Claude can't drive it. Check changes with build + vet, then have the user run `! go run .`.
To see a screen without a TTY, add a temporary `src/zz_*_tmp_test.go` that builds the model with a real `client.New`, sends it `tea.KeyMsg`s, runs any returned `tea.Cmd` and feeds the result back, then prints `View()` with ANSI codes stripped (`sed 's/\x1b\[[0-9;]*m//g'`). Delete it afterwards.

## Architecture

- `main.go` parses `-v/--version` and `-h/--help` (`version` is set by GoReleaser ldflags, else read from build info) and creates a `github.com/docker/go-sdk/client` `SDKClient`, which is what the whole TUI uses. `client.New` resolves the host from `DOCKER_HOST` or the current Docker context and runs a health-check ping. If that fails, `connect` runs `colima start` and retries once, but only if `colima` is on the PATH and `DOCKER_HOST` is unset; otherwise it prints how to start Docker. The author uses Colima, but the app must work with any daemon. API types come from `github.com/docker/docker/api/types/...`. Don't import `github.com/docker/docker/pkg/jsonmessage` (it drags in moby/term); `pullMessage` decodes the few fields needed.
- All screens live in package `src` and are independent `tea.Model`s. **Navigation works by returning a different model** from `Update` (e.g. `return InitLogsModel(...), l.Init()`); there's no router or parent model. Each screen builds its destination with an `Init*Model(dockerClient, ...)` constructor, and `esc` usually builds a fresh instance of the previous screen, losing its state. Going back to the home screen selects the card you came from (`withSelected`). The other exception is the logs view: it keeps the containers screen it came from (`logsModel.back`) and returns it on `esc` through `resume()`, which gives it a new tick id and the current size, so the cursor and expanded stacks survive. List screens keep the cursor on the same item across refreshes (`itemKey` / `imageRef`), not on the same row number.
  - `index.go`: home screen with one card per entry in `menuCards` (Containers, Images, Volumes, Networks, Exit), indexed by the `card*` constants. `cardGrid` uses the fewest rows that fit, spreading cards evenly (3 + 2, not 4 + 1); the big banner only shows when the grid is wider than the art. It has its own `indexKeys` keymap (←/→/h/l/tab to move, `enter` or `1`–`5` to open) and refreshes the card counts with `fetchSummaryCmd` on its tick loop.
  - `containers.go`: the containers table. `FetchContainers` groups containers by the `com.docker.compose.project` label into synthetic `compose_stack` rows. Stack rows show a summary (service count, all published ports, `n/m running`, state `running`/`partial`/`exited`), a ▸/▾ marker and no ID. `refresh` stores the fetch in `all`; `rebuild` applies the `/` filter, the `a` running-only toggle and the `o` sort (`containerSorts`) without refetching. A stack is listed if any service passes; its children show when its name is in `ShowChildrenSet` or the filter matched services rather than the stack name (`expanded`, `visibleChildren`). `Children` always holds every service, so stack actions act on the whole stack even when filtered.
  - `container_actions.go`: `planStartStop` / `planRestart` / `planPause` return a `containerPlan` (verb, targets, messages) that `containerPlanCmd` runs in parallel. `execShellCmd` (`e`) suspends the UI with `tea.ExecProcess` and runs `docker exec -it <id> sh -c '<bash or sh>'` through the docker CLI; `shellError` ignores the shell's own exit status and reports 126/127 as "no shell". `P` prunes stopped containers.
  - `stats.go`: CPU/memory columns. Each tick, if no fetch is in flight (`statsInFlight`), `fetchStatsCmd` samples every running container with `ContainerStatsOneShot` (fast, but no previous CPU reading), and `mergeStats` computes CPU % against the previous tick's `samples`, so CPU appears one tick after memory. Stack rows sum their services.
  - `inspect.go`: `i` on a container opens a read-only viewport of `ContainerInspect` sections. Like logs, it keeps the containers screen in `back` and returns via `resume()`.
  - `logs.go` / `logstream.go`: a viewport over `ContainerLogs` (last `hours`, default 1, which `t` changes through `numberField`), with timestamps, demuxed with `stdcopy` unless the container has a TTY. The range is fetched once; then `follow()` opens one `Follow: true` stream (`logStream`, cancelled by `stopFollowing` on esc and on reload) from just after the last timestamp shown. `waitLogs` delivers batches as `logLinesMsg` tagged with the stream id, and lines are appended with `appendCapped` (8 MB cap). A stream ends when the container stops; the tick starts a new one when it runs again (a follow on a stopped container would just replay and end, so it's only opened while running). `/` filters and highlights lines, `w` toggles wrapping (viewport horizontal step), `o` saves the shown lines to the current directory, `e` opens a shell. Each tick also inspects the container to show its state in the header (`describeContainerState`). If the container is deleted while open, the last logs stay on screen. `c` clears the view by setting `clearedAfter` to the timestamp of the last line shown, and later fetches pass it as `Since`. It uses the daemon's timestamp rather than the local clock because the Colima VM's clock can drift; `a` resets it. `s` starts or stops the container through the same `planStartStop` / `containerPlanCmd` as the containers screen.
  - `images.go`: the images table, refreshed every tick. `FetchImages` lists one row per tag (untagged images show as `<none>`, sorted last) and counts the containers (running or stopped) created from each image. `p` opens a pull field (pre-filled with the selected ref); `pullImageCmd` runs the pull in a goroutine that reports through buffered `pullChannels` (latest progress line + result), so it never blocks if the user leaves the screen. `P` prunes dangling images, `o` sorts (`imageSorts`).
  - `volumes.go` / `networks.go`: list screens built the same way. Which containers use a volume or network comes from `ContainerList` (mounts / `NetworkSettings.Networks` by network ID), because the list endpoints don't say. Deleting refuses anything in use and Docker's built-in `bridge`/`host`/`none`; volume prune passes `all=true` so named volumes go too (the prompt says so).
  - `input.go`: `textField` (one-line input; `numberField` is the digits-only variant) and `filterBar`, the `/` filter shared by every list and the logs. While `filter.editing`, the screen sends every key to it; `esc` on a screen first clears an active filter before going back. The filter shows as a `/query` breadcrumb (`withFilterCrumb`). Not bubbles `textinput`, which would pull in a clipboard dependency.
  - `help.go`: the shared `keyMap` (`keys`) used by `help.Model`, `containersKeys` for the containers screen, and `listKeyMap` (`imagesKeys`, `volumesKeys`, `networksKeys`) for the other lists. When you add a key to a screen, add it to that screen's keymap so it appears in the help. The logs and inspect footers list their keys by hand.
  - `layout.go`: the palette (`color*`: orange is brand and focus, steel blue is the selected row, green is running) and the shared list-screen layout. `renderHeader` draws the breadcrumb and counts, `renderPanel` the details box with its title in the border, and `renderBottomBar` the help and status. `listTableHeight` makes a list screen fill the window exactly, so call `layout()` after anything that changes the help height. Use `newHelp()` instead of `help.New()`. State glyphs are ● running, ◐ partial/paused, ○ stopped.
  - `starfield.go`: the animated sky behind the home screen. Three parallax layers drift left, each star twinkles on its own phase, and a shooting star comes every 8–20 s. It runs at about 10 fps on `frameMsg` ticks tagged with the home screen's `tickID`, so it stops when you leave. `compose` keeps a clear margin around the centred content and returns "" if the page doesn't fit, in which case the screen falls back to `lipgloss.Place`. Setting `STARDOCKER_REDUCED_MOTION=1` freezes it.
  - `confirm.go`: `confirmPrompt` holds a pending destructive action (`yes` labels the `y` key, default "delete"; prunes use "prune"). `actionMsg` is the result message for the volumes and networks screens. The action is built when the prompt opens, so later refreshes can't change its target. While a prompt is open the screen handles only `y`/`n`/`esc`, and the details panel is replaced by a red confirmation box. `statusLine` is the bottom-right message; successes clear themselves via `clearStatusMsg`. Delete rules: running containers are force-removed after the prompt warns about it, and volumes are never removed. An image that containers still use can't be deleted, but one of its extra tags can be removed.
  - Inside table cells, use glyphs, not colours: per-cell ANSI codes reset the selected row's background, and the table truncates cells without knowing about ANSI. `styles.go`: shared Lip Gloss styles and `tableStyles()` for every table screen.
- **Refresh loop:** each model that refreshes gets an id from `newTickID()`, starts its own loop in `Init()` with `tickCmd(id)`, and ignores any `tickMsg` whose id isn't its own. A tick still in flight from the previous screen therefore dies instead of stacking up a second loop.
- **Window size:** Bubble Tea sends `tea.WindowSizeMsg` only at startup and on resize, so every `Init*Model` constructor takes `width, height` from the screen it came from. Pass them along when you add a screen.
- **Rows vs. data:** table cells are display-only. `getRows` returns the rows plus a parallel `items` slice (the `Container` for each row), and actions use `selected()` (`items[cursor]`). The images screen does the same with `[]Image`. Keep the two slices in step if you change how rows are built.
- **Column widths:** column sets are `[]colSpec` (`containerColumns`, `imageColumns`). `fitColumns` (`src/columns.go`) sizes each column to its content and terminal width, shrinking by `shrinkOrder` (Ports shrinks last). It runs on every refresh and on resize. Spare width goes to columns with `grow`. Cells that still don't fit are truncated with `…`, so the details panel (`detailsBody` in `src/details.go`) under each table shows the selected row in full.
- Bubbles' table and viewport keymaps already bind `d`/`u` (half page), `f`/`b`/`space` (page) and `j`/`k`. A screen that adds one of these keys must handle it and `return` before passing the message to `table.Update` or `viewport.Update`.
- Models use value receivers, so mutations inside `Init()` are discarded. The containers table fills on an immediate first tick fired from `Init()`.
- Docker errors are shown in the UI (a status line or the log text). Container actions run as async `tea.Cmd`s that return `containerActionMsg`; images use `imageActionMsg`, volumes and networks `actionMsg`.
- Container-screen keys `r`, `p`, `e`, `i`, `o`, `a`, `P`, `/` don't collide with the bubbles table keymap; keep it that way.

## Releasing

CI (`.github/workflows/ci.yml`) runs gofmt, vet, build and test on PRs and main. Pushing a `v*` tag runs GoReleaser (`.goreleaser.yaml`), which publishes binaries for linux/darwin/windows × amd64/arm64 to a GitHub Release. A Homebrew tap is sketched (commented out) in `.goreleaser.yaml`; it needs a `homebrew-tap` repo and a `HOMEBREW_TAP_TOKEN` secret. `go.sum` is committed.

## Keybindings

See the README for the full per-screen tables. Lists: `/` filter, `d` delete, `P` prune, `esc` clear filter / back, `?` help, `q` quit. Containers add `enter` (logs / expand stack), `s` start/stop, `r` restart, `p` pause, `e` shell, `i` inspect, `o` sort, `a` running only. Images add `p` pull and `o` sort. Logs: `/`, `t`, `c`/`a`, `w`, `o` save, `s`, `e`, `G`.
